2. BIG TOP WILDS — FIXED REEL GEOMETRY
=====================================================================

Existing core geometry remains authoritative:

- 6 reels.
- Each reel independently has 2–6 visible symbol cells.
- Reel viewport width is fixed for the current breakpoint.
- Reel viewport height is fixed for the current breakpoint.
- Each reel width is constant.
- Only cell height changes according to reel row count.

For reel i:

cellHeight[i] = reelViewportHeight / rowCount[i]

rowCount is determined BEFORE visual spin animation begins.

During a spin:
- do not change reel viewport width;
- do not change reel viewport height;
- do not change row count;
- do not let image loading change geometry.

The Curtain feature is NOT an expanding multi-column feature.

A curtain ALWAYS occupies:
- exactly ONE reel/column in width;
- exactly 100% of that reel's visible height.

It must never become wider than one reel.
It must never cover adjacent reels.
It must never remain a one-cell tile.

This requirement applies at every row count:
2 / 3 / 4 / 5 / 6 visible cells.

Curtain overlay geometry:

curtain.left = reel.left
curtain.width = reel.width
curtain.top = reel.top
curtain.height = reel.height

Conceptually:

position: absolute;
inset: 0;

inside that reel's own positioning context.

Do not insert a curtain as a normal grid row item.
It is a reel-local overlay.

=====================================================================
3. SHOW TICKET — ONLY CURTAIN TRIGGER SYMBOL
=====================================================================

The approved trigger symbol is SHOW TICKET.

SHOW TICKET:
- occupies exactly ONE normal symbol cell;
- behaves visually like a normal reel symbol during the spin;
- is NOT a curtain;
- is NOT rendered on top of the curtain;
- is NOT a Wild;
- is NOT the Scatter;
- does NOT remain visible after the Curtain presentation starts;
- only triggers the Curtain event on the reel where it landed.

Do NOT use the previously generated spotlight as the trigger.
The spotlight file is included only as DEPRECATED_DO_NOT_USE... so there is
no ambiguity.

When SHOW TICKET lands:
1. all reels finish their normal stop animation;
2. ticket cell is briefly highlighted;
3. Curtain Feature starts on the SAME reel;
4. the ticket is visually replaced/covered by the curtain sequence.

If multiple SHOW TICKET symbols may be generated by configured math:
- each affects only its own reel;
- never stack more than one Curtain feature on the same reel;
- resolve multiple affected reels in deterministic left-to-right order unless
  the existing roundPlan explicitly stores a different approved sequence;
- the entire feature plan must be known before presentation begins.

The animation callback must never choose whether a ticket triggers.

4. EXACT CURTAIN VISUAL STATE MACHINE
=====================================================================

This is the mandatory sequence.

STATE 0 — FINAL REEL RESULT / TICKET VISIBLE
The normal reel spin has completed.
SHOW TICKET is visible in one cell.
All reel geometry is already final.

STATE 1 — REEL FOCUS
Briefly emphasize the affected reel.
Optional:
- soft marquee glow;
- neighboring reels slightly dimmed.
Do not move/resize the reel.

STATE 2 — CURTAINS CLOSE
A pair of real theater curtains enters from the LEFT and RIGHT edges of that
ONE reel and meets at the center.

Required look:
- red velvet;
- gold trim;
- top valance;
- theatrical depth;
- fills the entire reel height.

The curtains are not a one-cell image.
They are a full-height reel overlay.

Preferred animation:
leftCurtain: translateX(-100%) -> 0
rightCurtain: translateX(+100%) -> 0

Both halves meet at center.

Do NOT animate the reel width/height.
Animate internal curtain layers using transform.

STATE 3 — CURTAINS OPEN TO DUO SCENE
The same two curtain halves open horizontally.

Behind them is a FULL-HEIGHT theatrical scene.

The opened scene must:
- occupy the entire reel width;
- occupy the entire reel height;
- have a finished circus/stage BACKGROUND;
- contain no blank tan/transparent strip;
- contain no visible original symbol-cell backgrounds;
- look like one continuous full-reel illustration.

The scene contains BOTH:
- BOMBO
- SKINNY

Only these two.

They must be composed together as one deliberate duo illustration/scene,
not two unrelated crops pasted into separate cells.

Both characters should be readable across the full height:
- BOMBO lower/heavier;
- SKINNY higher/taller;
- interaction between them should be obvious.

They must look like the approved characters, not the random clowns shown in
some generated sequence mockups.

STATE 4 — CLOWN SHOWDOWN
Inside the already-open full-height curtain stage:
- BOMBO and SKINNY perform a short comic rivalry/showdown;
- all movement remains clipped to this reel;
- no body part may overlap adjacent reels;
- do not use fullscreen animation;
- do not move the entire slot.

Examples of acceptable comic motion:
- tugging;
- pointing;
- pushing;
- fake-out;
- prop interaction;
- exaggerated physical reaction.

The result is ALREADY stored in featurePlan.
Animation does not determine the winner.

STATE 5 — CURTAINS CLOSE AGAIN
After the duo scene/showdown:
- left and right curtains close to center again;
- they briefly hide the duo scene;
- this creates a clear visual transition between "contest" and "result".

STATE 6 — FINAL REVEAL
Curtains open again.

They remain OPEN in the final state.

Behind them:
- one and only one winner: BOMBO OR SKINNY;
- full-height circus/stage background;
- character integrated into the whole reel composition;
- clear result plaque/text.

Allowed result:
x1 => show ONLY "WILD"
x2 => show ONLY "x2"
x3 => show ONLY "x3"
x5 => show ONLY "x5"
x10 => show ONLY "x10"

Do NOT display:
WILD + x3
WILD x3
a small black x3 badge over WILD
two separate labels

Multiplier text REPLACES WILD for multiplier states.

The final reveal is a FULL REEL WILD logically.

STATE 7 — RESULT READY
Only after all final Curtain states have been resolved may the final paid
win evaluation/presentation occur.

7. DYNAMIC BIG TOP WAYS
=====================================================================

The game already has variable row counts.

The visible ways value must be DYNAMIC.

For a round:

BIG_TOP_WAYS =
rowCount[0] *
rowCount[1] *
rowCount[2] *
rowCount[3] *
rowCount[4] *
rowCount[5]

Example:
[4, 6, 3, 5, 4, 6]
=> 8,640 BIG TOP WAYS

Maximum:
6^6 = 46,656 BIG TOP WAYS

UI:
- show current round's actual value;
- never show a stale hardcoded value;
- update after reelHeights/rowCounts have been determined for the spin;
- preserve the same value through the entire presentation of that round;
- in bonus, show the current free-spin ways value too.

Visible wording:
"1 920 BIG TOP WAYS"
"8 640 BIG TOP WAYS"
etc.

Do NOT display the trademarked word MEGAWAYS.

Do not recalculate from DOM pixel sizes.
Use game state row counts.

10. BONUS CURTAINS — PERSISTENCE
=====================================================================

This is critical.

When a Curtain Wild has PLAYED/participated in a winning bonus result,
that Curtain becomes persistent for the bonus session.

Persistent means:
- it remains assigned to that reel between free spins;
- it is restored after reload;
- it is not replaced by ordinary reel symbols on the next free spin;
- its logical Wild/multiplier state remains associated with it according to
  the bonus state model.

Do NOT randomly move or redistribute persistent Curtains.
Do NOT add a vortex.
Do NOT invent a new movement mechanic.

A persistent curtain stays on its reel unless an explicit future specification
changes that rule.

Persist at minimum:
- curtainId;
- reelIndex;
- winnerClownId;
- multiplier;
- persistent status;
- bonusSessionId.

=====================================================================
11. WHEN A PERSISTENT BONUS CURTAIN OPENS
=====================================================================

A persistent Curtain must NOT sit permanently open.

For each bonus spin:

A. determine the final round result first;
B. determine whether each persistent Curtain PARTICIPATES in the current win.

IF the persistent Curtain participates in the current winning ways:
- highlight it;
- run its OPEN presentation;
- reveal its approved winner clown and WILD/xN state;
- it visually participates in the win.

IF the persistent Curtain does NOT participate:
- DO NOT open it;
- keep it CLOSED;
- emphasize it with a glow/pulse/highlight only;
- do not run the clown duo/showdown;
- do not show an open winner scene.

Therefore:

PLAYING CURTAIN:
closed -> opens -> winner visible -> win presentation

NON-PLAYING PERSISTENT CURTAIN:
closed -> highlighted/pulsed -> remains closed

Never open a curtain just because it exists.
