# Ревью VAULT и локальные оптимизации

База сравнения: опубликованный `3a7185c`. Изменения подготовлены в ветке `review/performance-and-state-safety`. По итогам ревью пользователь разрешил публикацию через GitHub Pages. Изменения production-БД не требуются.

Проверены общие auth/storage/wallet/sync, админка, Universal HUD, оба движка анимации, контроллеры/математика десяти игр, standalone-упаковка, статическая сборка и границы SQL/RLS. Это статическое ревью и локальные тесты; проверка production-политик/аккаунтов через административное подключение не выполнялась.

## Исправленные проблемы

| Приоритет | Проблема и последствия | Исправление |
|---|---|---|
| Высокий | `switchIdentity`, ветка повторной загрузки текущего аккаунта: после `await` отсутствовала проверка владельца. Старый ответ мог применить профиль/кошелёк/recovery после A→B. | Проверка `owner` и `identityEpoch` перед применением ответа и показом ошибки. |
| Высокий | `VaultProfileService.update`: завершившийся PATCH старого пользователя мог заменить профиль текущего и сохранить его в session marker. | UID фиксируется при отправке; ответ применяется только к исходной сессии. |
| Средний | Запоздалые ошибки синхронизации/админских запросов могли изменять статус или блокировку нового аккаунта. | Проверки владельца/epoch и поколения запроса перед обработкой ошибки. |
| Средний | Веб-страница ~32,7 МБ со встроенными изображениями: большой HTML нужно передавать и разбирать заново при обновлениях. | Только веб-сборка выносит изображения в `assets/embedded/<sha256>.<ext>`. Одинаковое содержимое хранится один раз; имена пригодны для кеширования. SDK data URL сохранён. |
| Средний | HUD каждые150 мс создавал форматтеры и повторял запись стилей/измерение баланса, включая неизменившуюся сумму. | Кеш `Intl.NumberFormat` и результат layout-проверки на DOM-узле. Инвалидация при смене текста/значения, resize и загрузке шрифтов. |
| Средний | Bird запускал RAF постоянно, включая лобби; физика в лобби не считалась, но callback выполнялся. | Сон цикла вне игры/при скрытой вкладке; возобновление с новым отсчётом времени и одним RAF. Активный расчёт физики/отрисовки сохранён. |
| Средний | Embed-скрипт многократно перезаписывал ~33 МБ и мог оставить промежуточный HTML после ошибки. | Преобразования в памяти, кеш чтения повторных ассетов, одна атомарная замена готового файла. |

## Измерения

Точные размеры текущей сборки: `reports/review-build.json`.

- Standalone:32 704 893 байта; веб-HTML:969 461 байт — уменьшение HTML примерно на97%.
- Внешние изображения:100 уникальных файлов,21 435 498 байт; байты каждого изображения совпадают с исходными.
- Сумма HTML+изображений до HTTP-сжатия примерно22,4 МБ. Это не обещание97% экономии всего трафика: картинки по-прежнему должны загрузиться и декодироваться. В проходе всех экранов браузер запросил98 уникальных изображений.
- Сто повторных отрисовок неизменившегося баланса:0 чтений `scrollWidth`. Изменение текста и ширины корректно отменяет кеш.
- Embed в одном сравнительном локальном прогоне:7,29→5,75 с; результат старого и нового упаковщиков побайтно совпал. Это ориентир одного запуска, не устойчивый benchmark.
- У Bird в лобби/скрытом документе нет продолжающейся RAF-цепочки; вход и возврат возобновляют её.

## Важные оставшиеся ограничения

1. **Клиентская игровая математика остаётся границей доверия.** RLS и проверка структуры/арифметики/round ID не доказывают, что клиент честно выбрал RNG seed. Для защищённого денежного кошелька нужен серверный план/settlement. В этом ревью не переносились RNG и выплаты на backend.
2. Корневой HTML остаётся большим автономным файлом, а eager preload части игр сохраняется. Новая веб-сборка облегчает документ и даёт отдельный кеш; полной ленивой загрузки игр/всех ресурсов пока нет.
3. Digital Derby/Poker и физический движок частично живут внутри standalone HTML; длинные функции runtime и несколько поколений миграций усложняют поддержку. Дальнейшее выделение модулей нужно делать отдельно с проверками восстановления. Замороженные legacy-модели нужны для существующих раундов и не удалялись.
4. Версия Supabase SDK сохранена. Обновление зависимостей и аудит уязвимостей стороннего кода — отдельная проверка, не результат этих тестов.

## Локальная проверка и будущая публикация

```bash
python3 tools/embed-vault.py
python3 tools/build-site.py
python3 -m http.server 8080 --directory _site
```

Открыть http://localhost:8080/. Для веб-размещения нужен **весь `_site/`**, включая `assets/embedded/`, а не один `_site/index.html`. Для передачи автономного файла использовать корневой `index.html`. Supabase localhost redirect/origin должны соответствовать настройке проекта.

Существующий GitHub Pages workflow уже публикует весь `_site` и получает hash именно веб-HTML. Он проверяет и публикует эту веб-сборку при обновлении main. Новая SQL-миграция не требуется.
