# BIG TOP WILDS — final handoff implementation

Status: local implementation; not published. Package `BIG_TOP_WILDS_FINAL_for_Codex_LITE.zip` overrides conflicting earlier requirements. Full package is preserved under `requirements/big-top-final-2026-10-22/`.

## Implementation

- Six fixed-width reels, predetermined2–6 rows. SHOW TICKET is one ordinary cell, non-paying/non-Wild/non-Scatter. One event maximum per owning reel. All outcomes are planned before animation.
- Real left/right velvet halves close the full column, open to Bombo/Skinny on one continuous stage, close again after showdown, reopen to one approved winner and remain open. The exact same plaque displays WILD or x2/x3/x5/x10.
- Final native portrait scenes retain complete faces; backgrounds fill the whole reel independently from proportional character rendering. No alternative clowns/spotlight trigger.
- Dynamic Ways uses plan.reelHeights; no DOM measurements, no cascades.
- Version3 bonus: any Curtain participating in a qualifying win persists on its SAME reel through the session. Stored identity: curtainId, reelIndex, winnerClownId, multiplier, persistent, bonusSessionId.
- On each subsequent spin, plan.curtainStates determines whether it opens the stored winner or stays CLOSED_HIGHLIGHTED with pulse only. Existing curtains suppress conflicting tickets on their own reel; no random relocation or vortex. New tickets on other reels get the complete duo sequence.
- Explicit resting visual state belongs to the plan; transitional CLOSED_IDLE/OPENING/OPEN_DUO/SHOWDOWN/CLOSING_AFTER_DUO/OPEN_WINNER states are exposed on reel-local stages.
- Stable progress stores persistentCurtains derived from completed spins. In-flight reload replays the same planned step; no reroll. Existing shared revisioned outbox, per-user cache, escrow and terminal bonus settlement are reused.
